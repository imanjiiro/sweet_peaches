ADR-001: Сравнение стратегий — фоновая задача, а не синхронный запрос

Статус: принято

Контекст: чтобы получить статистически устойчивые метрики (среднее и
максимальное время ожидания, загрузку врачей и т.д.), каждую из трёх
стратегий нужно прогнать не один раз, а N раз (сотни независимых
симуляций на одних и тех же параметрах). Один прогон — миллисекунды,
но N прогонов × 3 стратегии уже занимают секунды, а на большой нагрузке
или большом N — десятки секунд. HTTP-запрос столько не держат ни клиенты,
ни прокси по умолчанию.

Варианты:
  1. Считать синхронно внутри POST-запроса — просто, но запрос
     подвисает на десятки секунд, таймауты и плохой UX.
  2. Уменьшить N до значения, укладывающегося в синхронный ответ —
     легко реализовать, но статистика становится нестабильной,
     сравнение стратегий — недостоверным.
  3. Вынести расчёт в фоновую задачу: POST запускает задачу и сразу
     возвращает task_id, результат забирается отдельным запросом.

Решение: вариант 3. POST /api/simulation/compare отвечает 202 и
task_id; статус и результат отдаются через GET /api/tasks/{task_id} и
GET /api/tasks/{task_id}/result.

Последствия: API становится двухшаговым (запуск + опрос), это
дополнительный код на фронте и в web/, зато N можно держать
достаточно большим для достоверного сравнения, и сервис не блокирует
обработку других запросов на время расчёта.
