ADR-003: Динамическая стратегия — собственная очередь, а не simpy.PriorityResource

Статус: принято

Контекст: динамическая стратегия должна учитывать не только срочность
пациента, но и то, сколько он уже ждёт — иначе плановые пациенты могут
ждать бесконечно (starvation), что и требуется отследить при сравнении
стратегий. simpy.PriorityResource вычисляет приоритет пациента один раз,
в момент постановки в очередь, и больше не пересчитывает его, пока
пациент ждёт — а на этом и держится вся идея динамической стратегии.

Варианты:
  1. simpy.PriorityResource "как есть" — приоритет = срочность на
     момент поступления. Просто, но не даёт снижать эффект ожидания —
     то есть не реализует саму суть динамической стратегии.
  2. Периодически пересчитывать приоритет всех ожидающих и заново
     переставлять их в PriorityResource — требует вмешательства во
     внутреннюю очередь ресурса, не предусмотренного публичным API SimPy.
  3. Своя очередь поверх simpy.Resource: при освобождении врача сначала
     пересчитываем приоритет каждого ожидающего пациента (срочность +
     время ожидания) и сами выбираем, кого обслужить следующим.

Решение: вариант 3. Для FIFO и «жёсткой» приоритетной стратегии
используется штатный simpy.Resource/PriorityResource, а для
динамической — собственная очередь ожидания в core/strategies.py,
которая пересчитывает приоритет на каждый момент освобождения врача.

Последствия: три стратегии реализуются не единообразно — для
динамической требуется больше своего кода и отдельных тестов; зато
именно она даёт метрику starvation, ради которой всё сравнение
стратегий и затевалось.
