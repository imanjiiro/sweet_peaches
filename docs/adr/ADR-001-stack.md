# ADR-001. Выбор стека: Django + Django Ninja

Статус: принято
Дата: 2026-09-03

## Контекст

Это учебный проект — симулятор потока пациентов приёмного отделения
больницы. Нужен веб-интерфейс (форма запуска, список прогонов), модели
с ORM и миграциями, REST API для внешних клиентов, а вычислительная
логика симуляции должна быть отделена от web-слоя, чтобы её можно было
тестировать отдельно. В будущем симуляции могут стать длительными, и
это тоже нужно учитывать при выборе стека.

## Рассмотренные варианты

### 1. Django + Django Ninja

Плюсы:
- готовая ORM и система миграций (`manage.py migrate`);
- встроенная админка (`/admin`) — бесплатный просмотр и редактирование данных;
- готовые формы (`forms.py`) для валидации ввода;
- удобно сделать web и API в одном проекте;
- хорошо соответствует стеку, заданному курсом.

Минусы:
- нужно самим следить за разделением слоёв (`core/` не должен зависеть от Django).

### 2. FastAPI

Плюсы:
- простой и быстрый в написании API;
- удобен, если нужен только backend без HTML-страниц.

Минусы:
- админку, ORM и миграции нужно собирать отдельно (например, SQLAlchemy + Alembic);
- хуже соответствует требованиям курса, ориентированного на Django.

### 3. Flask

Плюсы:
- простой и минималистичный;
- лёгкий порог входа.

Минусы:
- ORM, миграции, админка, формы — всё нужно подключать и настраивать самостоятельно;
- нет готового набора инструментов, которые Django даёт из коробки.

## Решение

Выбрать Django + Django Ninja.

Django отвечает за web-интерфейс, модели, ORM, миграции и админку.
Django Ninja используется для REST API и автоматической
OpenAPI-документации (`/api/docs`). Вычислительная логика симуляции
находится в `core/` и не зависит от Django.

## Последствия

Положительные:
- единый web/backend стек без лишних сторонних инструментов;
- готовые модели, миграции и админка из коробки;
- API с автодокументацией через Django Ninja;
- `core/` остаётся независимым, поэтому в будущем расчёт можно будет
  вынести в отдельный механизм (очередь, фоновая задача), не трогая
  ядро.

Отрицательные:
- нужно соблюдать архитектурное разделение (`core/` не импортирует
  Django, views не содержат логики расчёта);
- Django добавляет больше структуры и шаблонного кода, чем минимальный
  FastAPI-сервис.
