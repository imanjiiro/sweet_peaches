```markdown
# Hospital Flow Simulation

## Идея проекта

Моделируем поток пациентов в приёмном отделении больницы: как они поступают, сколько ждут в очереди и как их обслуживают врачи. Задача — сравнить разные стратегии распределения пациентов между врачами (FIFO, Priority, Dynamic) и найти оптимальную для минимизации времени ожидания.

```

---

## Как работает система

```
Пациенты поступают
        ↓
Формируется очередь
        ↓
Выбирается пациент по стратегии (FIFO / Priority / Dynamic)
        ↓
Пациент обслуживается врачом
        ↓
Собираются и сохраняются метрики (в JSON)

```

Вычислительное ядро (`core/solver.py`) полностью работоспособно: поддерживает как детерминированный прогон по фиксированному списку пациентов (для тестов), так и имитационную генерацию пуассоновского потока с экспоненциальным временем приёма.

Расчёт запускается с веб-формы `/` или через API (`POST /api/tasks`) и выполняется **в фоне** через `threading.Thread`, не блокируя веб-сервер.

---

## Реперная точка (Эталонный тест)

* **Вход:** 1 врач, 3 пациента в момент `t=0.0` (время приёма каждого 5.0 мин, стратегия FIFO).
* **Ожидаемый выход:** задержки пациентов = `[0.0, 5.0, 10.0]`, среднее время ожидания = `5.0` мин, обслужено = `3`.
* **Проверка:** Ручной расчёт `(0 + 5 + 10) / 3 = 5.0 мин`. Тест реализован в `core/tests/test_solver.py`.

---

## Входные данные и Параметры

**Параметры веб-формы (`TaskForm`):**

* Количество врачей (`doctors`: от 1 до 20);
* Интенсивность прихода (`arrival_rate`: пац/мин, по умолчанию `0.15`);
* Среднее время обслуживания (`service_mean`: мин, по умолчанию `15.0`);
* Длительность смены (`horizon_min`: мин, по умолчанию `480.0` — 8 часов);
* Стратегия очереди (`strategy`: `fifo`, `priority`, `dynamic`).

---

## Фоновая обработка

Расчёт выполняется асинхронно через `threading.Thread` (`web/services.execute_run_async`). При создании задачи клиент мгновенно получает ответ `HTTP 202 Accepted` со статусом `queued`.

Статус задачи меняется по цепочке: `queued → running → done / failed`.

Каждый фоновый поток открывает собственное соединение с БД и корректно закрывает его через `connections.close_all()`.

  schemas.py        — Pydantic-схемы входных и выходных данных
  tests/            — unit-тесты ядра
web/                — Django-приложение
  models.py         — модель Task (хранение параметров и JSON-результатов)
  forms.py          — валидация параметров формы TaskForm
  views.py          — HTML-представления
  services.py       — бизнес-логика и запуск фоновых потоков (execute_run_async)
  api.py            — REST API на Django Ninja
  tests/            — интеграционные и API-тесты
docs/
  architecture.md   — архитектурный документ (12 разделов)
  ER.md             — ER-диаграмма сущности Task
  adr/              — записи архитектурных решений (ADR-001, ADR-002, ADR-003)

## REST API

Автоматическая OpenAPI-документация Swagger доступна по адресу: `/api/docs`.

| Метод | Путь | Код | Описание |
| --- | --- | --- | --- |
| `POST` | `/api/tasks` | 202 | Создать задачу и запустить фоновый расчёт |
| `GET` | `/api/tasks/{id}` | 200 / 404 | Полная информация о задаче и её статусе |
| `GET` | `/api/tasks/{id}/result` | 200 / 404 | Результаты вычислений завершённой задачи |
| `GET` | `/api/tasks` | 200 | Список всех задач |

## Быстрый запуск

1. **Клонирование и установка зависимостей:**
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

```


2. **Запуск миграций и сервера:**
```bash
python manage.py migrate
python manage.py runserver

```


3. **Запуск автоматических тестов:**
```bash
pytest

```



* Веб-интерфейс: [http://127.0.0.1:8000/](http://127.0.0.1:8000/)
* Документация API: [http://127.0.0.1:8000/api/docs](http://127.0.0.1:8000/api/docs)
